Time Complexity & Big O

How does an algorithm's run time grow when the input size $n$ explodes from 10 to 1,000,000? Big O notation discards hardware idiosyncrasies and constant factors to describe pure asymptotic growth rate.

The Formal Definition

Asymptotic Upper Bound

$$T(n) = O(g(n)) \iff \exists\, c > 0,\, n_0 > 0 \quad\text{s.t.}\quad T(n) \le c \cdot g(n) \quad\forall n \ge n_0$$

Common Hierarchy: $O(1) < O(\log n) < O(n) < O(n \log n) < O(n^2) < O(2^n) < O(n!)$

Symbol Definitions

SymbolMeaningDomain / Constraint
nInput size (e.g. number of items in array)Positive integer $n \ge 1$
T(n)Actual number of operations / execution stepsFunction of $n$
g(n)Asymptotic bounding function (e.g. $n, n^2, \log n$)Positive for sufficiently large $n$
cPositive constant multiplier absorbing machine speed$c > 0$
n_0Threshold input size past which the bound holds$n_0 > 0$

Competitive Programming Rule of Thumb

The 10⁸ Operations per Second Rule:

Modern CPUs typically execute roughly $10^8$ basic operations per second within a 1.0-second time limit:

  • $n \le 10^5 \implies O(n \log n)$ or $O(n)$ required ($10^5 \log_2 10^5 \approx 1.7 \times 10^6$ ops — easily passes).
  • $n \le 10^4 \implies O(n^2)$ will pass ($10^8$ ops max).
  • $n \le 25 \implies O(2^n)$ backtracking will pass ($2^{25} \approx 3.3 \times 10^7$ ops).
  • $n \le 11 \implies O(n!)$ permutations will pass ($11! \approx 3.9 \times 10^7$ ops).

Worked Example

Problem

Determine the Big O time complexity of searching a sorted array of 1,000,000 numbers using (A) Linear Search vs (B) Binary Search.

1
Linear Search ($O(n)$).
In the worst case (item is at the very end or absent), it must check all $1,000,000$ elements. Execution takes $\approx 1,000,000$ steps.
2
Binary Search ($O(\log_2 n)$).
Each comparison cuts the search space in half. The maximum number of checks is $\lceil \log_2(1,000,000) \rceil = 20$ comparisons.
✓ Linear search requires 1,000,000 comparisons; binary search requires only 20 comparisons — a 50,000× speedup!

Code Examples

#include <stdio.h>

/* O(log n) Binary Search */
int binary_search(const int arr[], int n, int target) {
    int low = 0, high = n - 1;
    while (low <= high) {
        int mid = low + (high - low) / 2;
        if (arr[mid] == target) return mid;
        else if (arr[mid] < target) low = mid + 1;
        else high = mid - 1;
    }
    return -1;
}

int main(void) {
    int arr[] = {2, 5, 8, 12, 16, 23, 38, 56, 72, 91};
    int idx = binary_search(arr, 10, 23);
    printf("Target found at index: %d (O(log n))\n", idx);
    return 0;
}
def binary_search(arr: list[int], target: int) -> int:
    """O(log n) search on a sorted list."""
    low, high = 0, len(arr) - 1
    while low <= high:
        mid = (low + high) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1

if __name__ == "__main__":
    data = [2, 5, 8, 12, 16, 23, 38, 56, 72, 91]
    print("Index of 23:", binary_search(data, 23))

Check Your Understanding

Q1. What is the best-case and average-case time complexity of Merge Sort?

Divide into 2 halves ($\log n$ levels), merging each level in $O(n)$ steps.
Merge Sort splits arrays logarithmically ($\log n$ levels) and merges in linear time at each level, achieving guaranteed $\Theta(n \log n)$ performance.

Q2. If an algorithm with $O(n^2)$ complexity takes 1 second for $n = 10,000$, how long will it approximately take for $n = 20,000$?

$(2n)^2 = 4n^2$. What is the scaling factor?
Because runtime scales with $n^2$, doubling the input size increases run time by $2^2 = 4\times$. Thus $1 \text{ s} \times 4 = 4$ seconds.

Q3. Why does Big O drop lower-order terms (e.g. $T(n) = 3n^2 + 100n + 5 \implies O(n^2)$)?

Think about asymptotic dominance as $n \to \infty$.
As $n \to \infty$, the highest power $n^2$ accounts for over 99.99% of total operations, making lower-order terms asymptotically insignificant.
