Permutations & Combinations

The central question of combinatorics is simple: does the order matter? When order matters (like a password or podium ranking), you use permutations. When order does not matter (like a poker hand or committee), you divide out the redundant permutations to get combinations.

The Formulas

Order Matters vs. Order Does Not Matter

$$P(n,r) = \dfrac{n!}{(n-r)!}$$ $$C(n,r) = \binom{n}{r} = \dfrac{n!}{r!(n-r)!} = \dfrac{P(n,r)}{r!}$$

Notice that $C(n,r)$ simply divides $P(n,r)$ by $r!$, collapsing all $r!$ internal orderings into 1 unique group.

Symbol Definitions

SymbolMeaningDomain / Constraints
nTotal size of the pool/set of distinct itemsNon-negative integer ($n \ge 0$)
rNumber of items being selected/arranged$0 \le r \le n$
n!Factorial: $n \times (n-1) \times \dots \times 1$By definition, $0! = 1$
P(n,r)Permutations (arrangements where order matters)Integer, $P(n,r) \ge C(n,r)$
C(n,r)Combinations (selections where order is ignored)Integer, symmetric: $\binom{n}{r} = \binom{n}{n-r}$

Conditions & Assumptions

Standard model assumptions:
  • Without replacement: Each item from the total $n$ can only be picked once. If replacement is allowed with order, the answer is $n^r$.
  • Distinct elements: All $n$ items in the pool are individually distinguishable.
  • $r \le n$: You cannot choose more items than exist in the set.

Worked Example

Problem

From a group of 8 volunteers: (A) in how many ways can a President, Vice President, and Secretary be elected? (B) In how many ways can a 3-person cleanup crew be chosen?

1
Part A — Roles are distinct, so order matters.
We compute $P(8, 3) = \dfrac{8!}{(8 - 3)!} = \dfrac{8!}{5!} = 8 \times 7 \times 6 = 336$ ways.
2
Part B — Cleanup crew roles are identical, so order does not matter.
We compute $C(8, 3) = \dfrac{P(8, 3)}{3!} = \dfrac{336}{6} = 56$ ways.
✓ Part A: 336 permutations · Part B: 56 combinations.

Code Examples

Multiplicative implementation preventing overflow without computing large factorials directly.

#include <stdio.h>

long long nPr(int n, int r) {
    if (r < 0 || r > n) return 0;
    long long res = 1;
    for (int i = 0; i < r; i++) {
        res *= (n - i);
    }
    return res;
}

long long nCr(int n, int r) {
    if (r < 0 || r > n) return 0;
    if (r > n - r) r = n - r; /* Symmetry optimization */
    long long res = 1;
    for (int i = 1; i <= r; i++) {
        res = res * (n - r + i) / i;
    }
    return res;
}

int main(void) {
    printf("P(8, 3) = %lld\n", nPr(8, 3));
    printf("C(8, 3) = %lld\n", nCr(8, 3));
    return 0;
}
import math

def permutations(n: int, r: int) -> int:
    """Computes nPr = n! / (n-r)!"""
    return math.perm(n, r)

def combinations(n: int, r: int) -> int:
    """Computes nCr = n! / (r! * (n-r)!)"""
    return math.comb(n, r)

if __name__ == "__main__":
    print("Permutations P(8, 3) =", permutations(8, 3))
    print("Combinations C(8, 3) =", combinations(8, 3))

Check Your Understanding

Q1. What is the value of $\binom{5}{2}$ (or $C(5, 2)$)?

$\frac{5 \times 4}{2 \times 1} = \frac{20}{2}$.
$C(5, 2) = \frac{5!}{2! 3!} = \frac{5 \times 4}{2} = 10$.

Q2. How does $\binom{10}{3}$ compare to $\binom{10}{7}$?

Choosing which 3 items to keep is identical to choosing which 7 items to leave behind.
Combinations are symmetric: $\binom{n}{r} = \binom{n}{n-r}$. Here $\binom{10}{3} = \binom{10}{7} = 120$.

Q3. Setting a 4-digit PIN code on a smartphone is an example of:

Does entering "1-2-3-4" unlock a phone with passcode "4-3-2-1"?
Because "1234" is distinct from "4321", sequence matters. Hence it is an arrangement (permutation with repetition).
